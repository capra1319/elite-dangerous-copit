## Free community use

You can use the app, study the code, make changes and share free,
noncommercial versions while retaining the copyright notice and license.
Clearly mark a fork as modified and credit the original project. Source and
binary redistribution are allowed subject to those conditions.

Ordinary gameplay use, including showing Co-pit during a monetized game
stream or recording, is permitted. That exception does not authorize selling
Co-pit, a derivative, or access to either.

## Monetized versions need a written agreement

Obtain a separate written agreement from CapraarpaC before monetizing Co-pit
or a derivative. Examples include selling builds, paid features, subscriptions,
hosted services, paid bundles, advertising, sponsorship, affiliate revenue,
or software-related donations, crowdfunding, paid support and customization.
The requirement applies to nonprofit distributors too. It applies even when
the app is free to download, the source is public, or expenses exceed income.

Making a derivative's source public does not waive the commercial agreement
requirement for the Co-pit code it contains. Applying another license to
your own additions does not relicense Co-pit's code or remove these terms.
Separately licensed, independent third-party code retains its own permissions.

No royalty rate has been set. Royalty percentages, the definition of revenue,
reporting, payment timing, exemptions and permitted uses must be agreed in
the separate written commercial contract. An inquiry or a payment alone does
not authorize monetization. Nothing here promises that a commercial license
will be offered or that an inquiry will be accepted.

## Requesting permission

Use the contact information that the maintainer makes available on
[capra1319's GitHub profile](https://github.com/capra1319). The canonical
repository is [elite-dangerous-copit](https://github.com/capra1319/elite-dangerous-copit).

For an initial inquiry, describe the product or fork, what Co-pit code it
would use, how it would generate revenue and whether its source would be
published. Agree on a private contact channel before sharing confidential
financial or contractual information. A public issue, if used, should only
request a way to discuss licensing; it is not itself a commercial agreement.

## Dependencies, contributions and review

Existing notices in [licenses/](licenses/) remain applicable. The project
license does not make CapraarpaC the owner of third-party code or give the
maintainer authority to offer commercial exceptions for someone else's work.
Contributors retain rights in their original work; a pull request alone does
not transfer copyright or automatically authorize the maintainer to license
that contribution commercially. Necessary contributor permissions must be
resolved before including such work in a commercial grant.

These are project-specific terms, not a standard open-source license. An IP
lawyer should review the license and any commercial agreement before the
maintainer relies on them for enforcement or signs a royalty arrangement.

The license concerns protected code and project materials; it does not claim
ownership of the general idea of a game companion or of independently
written software with similar functionality.
